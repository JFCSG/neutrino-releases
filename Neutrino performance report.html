Neutrino · enterprise evaluation

Higher throughput, lower energy per unit of work

Neutrino installs as a software layer on the Linux server you already run. It does not require new hardware. On the work measured here, jobs finish sooner, each token costs less energy, or both.

Measurement. Every figure is a single-host comparison against an unmodified control on the same machine. The live record and the September 2026 checks are kept separate and are not blended into a fleet average. CPU package energy and GPU energy are metered independently and are never added together. Green is energy. Blue is speed.

Coding assistant and short chat, on the live server

Taken from the host that is running Neutrino, against an untouched control on that host. These are not identical outputs: the assisted answers were longer.

Coding assistant · energy
−28%

7.75 → 5.60 joules per token

Token rate rose from 37 to 54 a second, a 46% gain. The assisted answer was longer, about 2,000 tokens against 800, so completion time moved from 19 seconds to 35. The energy gain is per token, not a shorter job.

Short chat · energy
−9%

4.55 → 4.16 joules per token

A short reply still returns in about two seconds.

Repeated CPU work

Mean of five matched runs of each job, on the same host, in September 2026. Input and result matched on both sides. This is one server, not a cluster.

Repeated batch work · energy
−58%

92 → 39 joules

The job is 60% shorter, 5.2 seconds to 2.1. On this host, that is about two and a half times as many of these jobs in an hour.

Order commits · energy
−94%

456 → 27 joules

Time falls 94%, from 25 seconds to 1.5. About seventeen times the job rate. The result checksum matched.
